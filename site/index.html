Methodology, Calibration & Caveats
How real quota burn is measured, API-equivalent formulas, statistical uncertainty, and known limitations

1. How We Measure Monthly Capacity

We run autonomous multi-turn coding tasks inside isolated containers using the actual Antigravity and Codex harnesses, recording exact token usage and net quota burn. Because task difficulty cancels out of the API-cost-to-quota-burn ratio, we scale each pool's implied monthly API value onto Artificial Analysis Intelligence Index v5 tasks.

Implied Pool $/mo = (API Cost ÷ Quota Burn Fraction) × 4.33 Tasks / Month = Implied Pool $/mo ÷ AA Cost per Task

2. Real Sessions vs. Theoretical Token-Only

We also run 3 synthetic probes (input-heavy, output-heavy, cache-heavy) per model to fit per-token quota weights. On Gemini 4 Neon, real multi-turn Antigravity sessions burn ~15–35% more quota than synthetic weights alone predict—so we default to the real-session numbers as the realistic user experience.

Token-Weighted Tasks/mo = (100 × 4.33) ÷ (w_in·T_unc + w_cache·T_cache + w_out·T_out)

3. Effort Scaling & Confidence Intervals

  • Measured vs. Scaled: Solid dots are directly measured runs; hollow dots are scaled from each family's measured anchor using Artificial Analysis per-effort cost ratios.
  • Uncertainty: 95% confidence intervals use leave-one-out Student-t jackknife on continuous quota meters and exact ±1% quantization bounds on Codex Free.

4. Important Caveats

  • Full Weekly Usage: Chart baselines assume 100% weekly quota utilization without 5-hour cap waste. Use the Quota Planner above to model realistic 50–80% usage.
  • Claude Cache Writes: Antigravity does not separate cache-write tokens from uncached input (~10–13% upper-bound shift on Claude models where cache write = 1.25× input).
  • Open Source: All experiment manifests, calibration scripts, and raw CSVs are available in the GitHub repository.
