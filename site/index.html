Takeaway 1: Go Neon-First on Antigravity

Because Gemini 4 Neon and Hydrogen share the same gemini-weekly quota pool, Neon's efficiency makes it strictly preferable across almost every intelligence target: Neon Low beats Hydrogen Medium on both intelligence (44.1 vs. 41.2) and volume (352 vs. 263/mo), while Neon Medium (54.9 @ 154/mo) beats Hydrogen xHigh (53.9 @ 66/mo) by 2.3×.

Takeaway 2: Rapid Subscription Value Expansion

On Nov 7, Google AI Pro capped out at 50.4 AA (15 tasks/mo on Argon High) or ~30.8 AA (57–77 tasks/mo on 3.8 Flash). Within two weeks, Hydrogen and Neon pushed the same $19.99/mo subscription up to 61.4 AA while multiplying monthly task throughput by 3–5× at comparable intelligence.

Methodology, Calibration & Caveats

Full code, experiment configs, and raw report CSVs are open-source in the repository so anyone can audit or reproduce the numbers.

1. Primary Projection (Real Multi-Turn Subbench)

Subbench runs autonomous coding tasks inside isolated Docker containers using real agy / codex sessions, recording exact token usage and net contiguous quota burn (netting inter-attempt backend recredits). When a 5h bucket is present, weekly-equivalent burn uses 5h / ratio (3.50 for gemini-5h, 2.00 for 3p-5h).

Implied Pool $/mo = (api_cost_usd / total_burn_frac) × 4.33 AA Tasks/mo = Implied Pool $/mo ÷ AA_II_v5_cost_per_task

Because SWE-bench task difficulty cancels out of the API-cost-to-burn ratio, monthly throughput scales cleanly onto Artificial Analysis Intelligence Index v5 tasks while preserving real multi-turn harness and caching overhead.

2. Alternative Projection (Theoretical Token-Only)

To isolate provider quota metering from harness overhead, we run 3 synthetic probes (input_heavy, output_heavy, cache_heavy) per model and fit non-negative least-squares weights (w_in, w_cache, w_out) in weekly percentage points per 1M tokens, then multiply by AA's public per-task token mix:

burn_per_task_pp = w_in·T_unc + w_cache·T_cache + w_out·T_out Token-Weighted Tasks/mo = (100 × 4.33) ÷ burn_per_task_pp

On Gemini 4 Neon, real multi-turn agy sessions burn ~15–35% more quota than synthetic 3-prompt weights predict (Subbench / Token-Weighted = 0.69×–0.83×), making Primary the realistic user throughput and Token-Weighted an upper-bound baseline.

3. Uncertainty & Effort Scaling

  • 95% Confidence Intervals: Leave-one-out Student-t jackknife across valid attempts for continuous quota buckets; exact ±1 pp quantization bounds for codex-30d.
  • Effort Scaling: Unmeasured effort levels (hollow markers) are scaled from each family's measured anchor cycle using AA's exact per-effort cost_per_task ratio (Primary) or per-effort token breakdown (Token-Weighted).
  • Settling: Cycles 4–10 pre-date post-attempt quota settling checks; numerical CIs are shown in tooltips and tables and can be toggled on the chart.

4. Key Caveats & Transparency

  • Weekly Utilization: Baseline monthly figures (× 4.33) assume 100% weekly quota utilization without 5-hour cap waste. Use the interactive Quota Planner above to model realistic 50–80% utilization.
  • Anthropic Cache-Write Reporting: agy does not separate cache_write_tokens from uncached input (~10–13% upper-bound shift on Claude models where cache write = 1.25× input).
  • Weight Fallbacks: Models whose synthetic input_heavy probe was masked by a background recredit (3.8 Flash, Hydrogen) fall back to joint-fit weights in the Token-Weighted view.
